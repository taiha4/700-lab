# プログラム仕様書 — 700 Lab

TOEIC 700 点突破を目指す社会人向け英単語アプリ（Expo / React Native）

- 版数: v1.0（初版・2026-08-14）
- 元要件: `doc/app-spec.txt`
- 単語データ: `doc/toeic_wordlist.xlsx`（300 語）
- 参考デザイン: `~/Claude/dev/KouxaPlatform_2`（My Growth Lab トーン）

## 1. プロダクト概要

| 項目 | 内容 |
|------|------|
| アプリ名 | **700 Lab**（ナナヒャク・ラボ） |
| タグライン | 今日の 15 分が、700 点をつくる。 |
| 想定ユーザー | 30 代の社会人。TOEIC 500〜650 点。学習時間は通勤 30 分（往復で 2 枠）と昼休み 15 分のみ |
| 1 回の学習 | **1 セット = 10 問 / 所要 5〜15 分**（設定で 8 / 10 / 12 問） |
| 提供価値 | 「意味が分かる」で止めず、**ビジネス文脈で使える状態**まで運ぶ。間違いは必ず**理由まで**返す。進捗は**推定スコア**で見える |
| 動作環境 | Expo Go（SDK 54）。ログインなし・サーバーなし・端末内 AsyncStorage のみ |
| 外部通信 | Gemini API（`gemini-2.5-flash`）への直接 HTTPS 呼び出しのみ |

### 1.1 コンセプトの核 — 3 つの課題への回答

要件で挙げられた 3 課題すべてに、体験レベルで回答する。

| 課題 | 本アプリの回答 | 実装機能 |
|------|----------------|----------|
| ①「覚えた」と「使える」は別物 | 1 語を **認識（Recognize）／運用（Use）の 2 段階**で管理し、セットの後半は必ず「ビジネス文脈の穴埋め」で出す。単語帳も 2 軸で表示する | §4.2 出題エンジン、§4.4 二軸マスタリー |
| ② 間違えた原因が分からない | 不正解時に Gemini が誤答を **4 タイプに分類**（類似語混同 / 品詞ズレ / 記憶あいまい / 文脈読み違い）し、先生口調で「なぜ」と「次の見分け方」を返す。タイプは蓄積され**誤答カルテ**になり、**次回の出題内容を変える** | §4.3、§5.2、§4.6 |
| ③ 続けても実感がない | 学習データから **700 点メーター（推定到達スコア）** を算出。セット終了時に「今日 +2.4 pt 前進」と差分で提示。式は §6 で公開し、ブラックボックスにしない | §6 推定スコア |

### 1.2 既存アプリにない仕掛け（差別化ポイント）

1. **誤答カルテ（Error Chart）** — 間違いを AI が原因タイプで分類・蓄積し、「あなたは類似語の取り違えが 47%」と可視化。さらに**弱点タイプに応じて次セットの問題形式そのものが変わる**（類似語混同が多い人は、選択肢に `require / request / demand` のような類似語が優先的に混ざる）。正誤だけを記録する既存アプリにはない。
2. **二軸マスタリー（認識 × 運用）** — 同じ 1 語が「意味は分かるが使えない」状態として明示的に可視化され、運用問題に昇格するまで「習得済み」にならない。
3. **モード選択（通勤 / 昼休み）** — 「通勤モード（音を出さず・片手・10 問）」「昼休みモード（8 問・復習重視）」を起動時に 1 タップで選べ、迷う時間をゼロにする。

## 3. データ設計

### 3.1 単語マスタ（`src/data/toeic_wordlist.json`・300 件・読み取り専用）

`doc/toeic_wordlist.xlsx` の「TOEIC単語リスト」シートを `scripts/build-wordlist.ts` で変換する。

```ts
type Word = {
  id: number;            // 1..300
  word: string;          // "provide"
  pos: string;           // "動詞" / "名詞/動詞" / "名詞句" 等（原文どおり）
  posTags: PosTag[];     // ["verb"] — pos を "/" 分解して正規化（品詞ズレ判定に使用）
  meaning: string;       // "提供する・与える"
  meanings: string[];    // "・" 分解
  level: 1 | 2 | 3;      // ⭐数から算出（L1:40件 / L2:110件 / L3:150件）
  scene: string;         // "メール・報告"
  similar: string[];     // ["supply","offer","give"] — "," 分解
};
```

### 3.2 学習状態（AsyncStorage）

| キー | 型 | 内容 |
|------|----|------|
| `@700lab/v1/progress` | `Record<number, WordProgress>` | 単語ごとの学習状態 |
| `@700lab/v1/sessions` | `SessionRecord[]`（最大 100 件で古い順に破棄） | セット履歴 |
| `@700lab/v1/settings` | `Settings` | 問題数 / 対象レベル / モード / APIキー |
| `@700lab/v1/aiCache` | `Record<string, CachedAI>`（最大 300 件・LRU） | Gemini 応答キャッシュ（オフライン再表示用） |
| `@700lab/v1/schema` | `number` | スキーマ版数（マイグレーション用） |

```ts
type Stage = 'new' | 'recognized' | 'using' | 'mastered';
// new: 未学習 / recognized: 意味選択に正答 / using: 文脈問題に正答 / mastered: 文脈問題に間隔をあけて2回連続正答

type ErrorType = 'confusion' | 'pos' | 'memory' | 'context';
// confusion: 類似語混同 / pos: 品詞の取り違え / memory: 記憶があいまい / context: 文脈で意味がずれた

type WordProgress = {
  wordId: number;
  stage: Stage;
  recognizeCorrect: number; recognizeWrong: number;
  useCorrect: number;       useWrong: number;
  streak: number;            // 連続正解
  ease: number;              // 1.3–2.8（SM-2 ライト）
  intervalDays: number;
  dueAt: string;             // ISO
  lastAnsweredAt: string | null;
  errorTypes: ErrorType[];   // 直近 5 件
  lastChoiceWrong: string | null; // 直近の誤答選択肢
};

type SessionRecord = {
  id: string; startedAt: string; finishedAt: string;
  mode: 'commute' | 'lunch';
  answers: { wordId: number; format: 'recognize' | 'use'; correct: boolean;
             chosen: string; ms: number; errorType?: ErrorType }[];
  accuracy: number;          // 0–1
  scoreBefore: number; scoreAfter: number;  // 推定スコア
  summary: string | null;    // Gemini 総括
  nextAdvice: string | null; // 次回への一言
};
```

- 起動時に `progress` が空なら 300 語ぶんを `stage:'new'` で初期化する。
- スキーマ版数が異なる場合はマイグレーション関数を通す（v1 では初期化のみ）。

## 4. 機能仕様

### 4.1 画面一覧

| ルート | 画面 | 主な内容 |
|--------|------|----------|
| `/(tabs)/` | ホーム | 700 点メーター（大）・今日の進捗・連続日数・「通勤モード / 昼休みモード」の 2 ボタン |
| `/session` | 出題 | 10 問（進捗ドット・問題カード・回答後フィードバックカード） |
| `/session/summary` | 総括 | 正解数・所要時間・スコア差分・誤答タイプ内訳・Gemini 総括と次回への一言 |
| `/(tabs)/progress` | 進捗 | 数値 KPI・7 日間の学習量バー・二軸マスタリー・誤答カルテ・要注意語 Top5 |
| `/(tabs)/words` | 単語帳 | 300 語一覧（検索 / レベル / 状態フィルタ）。行に二軸バッジ |
| `/word/[id]` | 単語詳細 | 意味・品詞・場面・類似語・自分の履歴・保存済み例文 |
| `/(tabs)/settings` | 設定 | Gemini API キー・1 セット問題数・対象レベル・キャッシュ削除・全データリセット |

### 4.2 出題エンジン（`selectQuestions.ts`）

**1 セット = 10 問（設定で 8/12）。認識問題と運用問題を必ず混ぜる。**

出題枠の配分（10 問時）:

| 枠 | 問題数 | 選定条件 |
|----|--------|----------|
| A. 復習（期限到来） | 最大 4 問 | `dueAt <= now` の語を `dueAt` 昇順。stage に応じて形式を決定 |
| B. 運用チャレンジ | 3 問 | `stage === 'recognized'` の語 → **必ず運用（文脈穴埋め）形式** |
| C. 新規 | 3 問 | `stage === 'new'` かつ対象レベル内。ユーザーの推定スコア帯に合わせ L1→L2→L3 の順に投入 |

- 枠が埋まらない場合は他枠から補充し、**常に規定問題数を満たす**。
- 同一セット内に同じ単語を 2 回出さない。
- 直近セットで出題した語は原則除外（復習期限が来ている語を除く）。

**問題形式**

| 形式 | 出題 | 選択肢 |
|------|------|--------|
| `recognize`（認識） | 英単語 + 品詞を提示し、日本語の意味を 4 択 | 正解 1 + ダミー 3（§4.5） |
| `use`（運用） | ビジネス文脈の英文の空欄を 4 択で埋める。文は Gemini が生成（フォールバックあり） | 正解 1 + **類似語列から 3**（`similar` が 3 未満なら同一品詞・同一場面の語で補完） |

### 4.3 回答〜フィードバック（1 問あたり）

1. ユーザーが選択肢をタップ → 即座に正誤を色で表示（正: ローズ、誤: 落ち着いた朱）。**この時点で待たせない。**
2. **不正解のときだけ** Gemini へ 1 リクエスト（§5.2 プロンプト B）。応答が返るまでフィードバック欄はスケルトン表示。正解のときはセット開始時に取得済みの内容（§5.2 プロンプト A）を即座に表示し、API は呼ばない。
3. 返却内容（正誤共通で **ビジネス文脈の例文**、不正解時のみ **誤答分析** が付く）:

```
┌──────────────────────────────┐
│ ✗ 不正解                              │  ← 即時
│ ── なぜ間違えたか（先生より）──        │
│ 【類似語の混同】                       │  ← errorType（バッジ表示）
│ requireとrequestを取り違えましたね。    │
│ requireは「制度・規則が要求する」…      │
│ 見分け方: 主語が人なら request です。   │
│ ── ビジネスでの使い方 ──               │
│ All applicants are required to submit  │
│ the form by Friday.                    │
│ （応募者は金曜までに提出が必要です）     │
│ 場面: 要件・依頼                       │
└──────────────────────────────┘
[ 次の問題へ ]
```

4. `errorType` を `WordProgress.errorTypes` に追加し、SRS を更新（§4.7）。

> **AI 応答の破棄条件（v1.5）**: 解説の取得は非同期のため、応答が返る前に「次へ」で進める場合がある。**応答が解決した時点で表示中の問題番号が回答時と異なる場合、その解説は表示せず破棄する**（記録は既に確定しているので学習データには影響しない）。これを怠ると、前の問題の解説が次の問題の画面に表示される。

> **記録タイミングの仕様（v1.3・重要）**: 回答の記録・学習状態の更新・永続化は、**選択肢をタップした瞬間に同期的に完了させる**。AI 応答の解決後に記録すると、上記 3 の解説を待たずに「次へ」を押した回答が保存されず消えるため（待ち時間中も進めることは §4.3 の要件）。誤答タイプだけは AI 応答後に、記録済みの回答と単語の学習状態へ追記する。セット確定後に応答が返った場合はセッション履歴側を更新する。
5. 例文は `aiCache` に保存し、単語詳細画面とオフライン時に再利用する。

### 4.4 二軸マスタリー表示

進捗タブに 2×2 のマトリクスで語数を表示する。

```
            使える(運用○)      使えない(運用×/未挑戦)
分かる      🟢 mastered/using   🟡 recognized  ← ここが「覚えたのに使えない」層
分からない  —                   ⚪ new
```

- 🟡 の語数を「**使えるに変えたい語**」として明示し、そのままセット開始できる導線を置く。

### 4.5 選択肢生成（`buildChoices.ts`）

正解 1 + ダミー 3。ダミーの選び方は**ユーザーの誤答傾向で変える**（差別化ポイント）。

| ユーザーの最頻誤答タイプ | ダミーの優先順 |
|--------------------------|----------------|
| `confusion`（既定はこれ） | ① 同語の `similar` に載る語の意味 → ② 同じ場面の語 → ③ 同レベルの語 |
| `pos` | ① 同じ語幹で品詞違いの語 → ② 異なる品詞の同レベル語 |
| `memory` / `context` | ① 同じ場面の語 → ② 同レベルの語 |

- 選択肢は毎回シャッフルし、正解位置に偏りが出ないようにする。
- 意味が重複するダミーは除外する。

**データ実測に基づく補足（v1.2）**: `similar` 列の 860 語のうち、単語マスタ 300 語に実在するのは 101 語（順方向 + 逆引きでも、類似語を master 内に持つ語は 109/300）。したがって:

- **`use` 形式**（英単語 4 択）では `similar` の文字列をそのまま選択肢にできるため、**全 300 語で「類似語混同」対策が成立する**。混同への回答はこちらが主戦場となる。
- **`recognize` 形式**（日本語の意味 4 択）は、類似語の日本語訳を得るために master 内に実在する必要がある。そのため ① 順方向 + 逆引きで得た master 内の類似語 → ② 同じ品詞かつ同レベル → ③ 同レベル、の順に劣化フォールバックする。

### 4.6 誤答カルテ

- 全 `SessionRecord.answers` の `errorType` を集計し、**ドーナツグラフ + 件数 + 割合**で表示。
- 最頻タイプに応じて 1 行のコーチング文を出す（例: 「あなたの弱点は**類似語の混同**。次のセットでは紛らわしい語をあえて選択肢に混ぜます」）。
- この最頻タイプが §4.5 のダミー選定に直結する（**分析が出題に還元される**）。

### 4.7 間隔反復（`srs.ts`・SM-2 ライト）

| 結果 | ease | interval（日） |
|------|------|----------------|
| 正解 | +0.1（上限 2.8） | `streak` に応じて 1 → 3 → 7 → 14 → 30 |
| 不正解 | −0.2（下限 1.3） | 0（当日再出題対象）。`streak = 0` |

- `dueAt = 今日 + round(interval × ease / 2.5)` 日。
- stage 遷移: `new` → 認識正解で `recognized` → 運用正解で `using` → 運用で間隔をあけて 2 回連続正解で `mastered`。運用で不正解なら `using` → `recognized` に降格する。

## 5. Gemini API 仕様

### 5.1 共通

- エンドポイント: `POST https://generativelanguage.googleapis.com/v1beta/models/gemini-2.5-flash:generateContent`
- 認証: ヘッダ `x-goog-api-key`。キーは ① `.env` の `EXPO_PUBLIC_GEMINI_API_KEY`、なければ ② 設定画面で入力し AsyncStorage に保存した値。
  - **注意**: ログイン・サーバーを持たない構成のためキーは端末側に置く。本アプリは学習用途／デモ用途である旨を設定画面に明記する。
- 出力は必ず構造化 JSON（`responseMimeType: "application/json"` + `responseSchema`）。
- タイムアウト 12 秒、失敗時は 1 回だけ再試行。それでも失敗した場合はローカルのフォールバック文言を表示し、**学習フローは絶対に止めない**。
- 温度 0.7、`maxOutputTokens` 512（総括は 768）。

### 5.2 プロンプト設計

**system 指示（全リクエスト共通）**

```
あなたはTOEIC指導歴20年のベテラン英語講師です。生徒は30代の社会人で、
通勤と昼休みのスキマ時間だけで TOEIC 700 点突破を目指しています。
次のルールを必ず守ってください。
1. 口調は「先生が目の前の生徒ひとりに語りかける」ように。です・ます調で、
   温かく、しかし具体的に。「頑張りましょう」だけの精神論は禁止。
2. 一般論を書かない。渡された「この生徒の回答・履歴」に必ず言及する。
3. 例文は必ずビジネス実務の場面（渡された『場面』）に沿ったものにする。
4. 日本語の解説は 120 字以内。冗長な前置きは書かない。
```

**プロンプト A — 語ごとの教材の一括生成**（セット開始時に **1 回だけ**・出題する全語ぶん）

渡す情報: 出題する全語の `word / pos / meaning / scene / similar / level`、穴埋め問題を作る語の指定、この生徒の学習状況（総学習語数・正解率・推定スコア・最頻誤答タイプ）

```
出力: { items: [{ wordId, nuance, howToTell, example, exampleJa,
                  sentence?, translation?, distractors[3]? }] }

全語に必要:
- nuance: この語の「勘所」。正解した生徒に見せる一言（120字以内）
- howToTell: 似た語と迷ったときの見分け方（1文・similar に具体的に触れる）
- example / exampleJa: 「ビジネス場面」に沿った英文 1 文とその和訳

穴埋め問題を作る語だけ:
- sentence: 空欄を "____" で表した 1 文（12〜20 語）。TOEIC Part5/6 相当
- translation: その和訳
- distractors: 文法的には入りうるが意味的には誤りの語 3 つ（similar から優先）
```

例文と勘所をここで先に用意することで、**正解時は API を一切呼ばずに済む**（§5.2.1）。

**プロンプト B — 誤答分析**（**不正解のときだけ** 1 回）

生徒が実際に選んだ答えは事前に分からないため、ここだけは都度の呼び出しが必要。例文は A で用意済みなので生成させない。

渡す情報:
```
単語: require / 品詞: 動詞 / 意味: 必要とする・要求する
ビジネス場面: 要件・依頼 / 混同しやすい類似語: need, demand, request
出題形式: 意味選択（4択）
生徒の回答: 「依頼する」（不正解） / 正解: 「必要とする・要求する」
この生徒の履歴: この語は過去 2 回中 2 回不正解。直近の誤答タイプは
  類似語混同 3 回 / 品詞ズレ 1 回。総学習語数 84 語・全体正解率 71%。
```
```
出力スキーマ:
{
  "errorType": "confusion" | "pos" | "memory" | "context",
  "why": string,        // なぜ間違えたか（先生口調・120字以内・生徒の選んだ語に言及）
  "howToTell": string   // 次回の見分け方（1文・具体的に）
}
```
- 正解時はこの呼び出しを行わず、A の `nuance` / `howToTell` / `example` をそのまま表示する。

**プロンプト C — セット総括**（10 問終了後 1 回）

渡す情報: 正解数・所要時間・出題語と各正誤・誤答タイプ内訳・今回上がった推定スコア・連続学習日数・直近 3 セットの正解率推移・「使えない層（recognized）」の語数

```
出力スキーマ:
{
  "summary": string,      // 今日の学習の総括（200字以内・数字と具体語に必ず言及）
  "strength": string,     // 今日よかった点（1文）
  "focus": string,        // 次回の重点（1文・具体的な語やタイプを名指し）
  "nextWords": number[]   // 次回に再挑戦させたい wordId を最大3件
}
```

### 5.2.1 API 利用量と無料枠の制約（v1.5・重要）

**実測**: `gemini-2.5-flash` の無料枠は **1 日 20 リクエスト**（`GenerateRequestsPerDayPerProjectPerModel-FreeTier` = 20）。

**旧設計**は 1 セット（10 問）で 12 回消費していた（バッチ 1 + 毎問 10 + 総括 1）。無料枠では 1 日 1.6 セットしか回せず、最後に呼ぶ総括（AC-06）から犠牲になっていた。

**現在の設計**（v1.6）は次のとおり。

| 用途 | 回数 |
|------|------|
| プロンプト A（全語の教材を一括生成） | 1 |
| プロンプト B（誤答分析） | **誤答した数だけ** |
| プロンプト C（セット総括） | 1 |
| **合計** | **1 + 誤答数 + 1** |

10 問中 3 問誤答なら 5 回。全問正解なら 2 回。無料枠でも **1 日 4 セット前後**回せる。
（実測: 10 問中 6 問誤答のセットで 8 回。旧設計なら 12 回）

なお全問誤答の場合は 12 回で旧設計と並ぶが、正答率が上がるほど消費が減る構造になっている。

対応（実装済み）:
- 429 を `rate-limit`（分あたり・待てば回復）と `quota-daily`（1 日あたり・待っても回復しない）に区別する。
- 分あたりの制限は総括に限り最大 35 秒待って再試行する（ユーザーが結果を読んでいる間に取れる）。出題中は待たせないので待機なしでフォールバックする。
- 理由に応じた案内文を表示し、総括には再取得ボタンを置く。

**トレードオフ**: セット開始時の 1 回で全語ぶんを生成するため、開始待ちがやや長くなる（出力トークンが増えるため）。また 1 回の失敗で全語がテンプレートに落ちるが、テンプレートは品詞別に用意してあり学習は成立する。

### 5.3 フォールバック（API 失敗時・キー未設定時）

| 用途 | フォールバック |
|------|----------------|
| 運用問題の文 | 単語データの `scene` を使ったテンプレート文（`This report ____ detailed sales data for Q3.`） |
| 誤答分析 | `similar` を用いた定型解説（「`request` と混同しやすい語です」）+ 「AI 解説は現在取得できません」の注記 |
| 総括 | ローカル集計のみの総括文（正解数・スコア差分・弱点タイプ） |

## 6. 700 点メーター（推定スコア）

「今日の学習が 700 点にどれだけ近づいたか」を数値化する。**計算式はアプリ内（進捗タブの ⓘ）で公開する。**

```
推定スコア = 450 + Σ_語 ( レベル重み × 段階係数 ) × 正解率補正   （上限 990・下限 400）

レベル重み: L1 = 0.45 / L2 = 0.70 / L3 = 0.89
段階係数:  new 0 / recognized 0.4 / using 0.8 / mastered 1.0
正解率補正: 0.9 + (直近50問の正解率 × 0.2)   → 0.9〜1.1
```

- 全 300 語が `mastered` かつ正解率 100% のとき ≒ 700 点に到達する設計。実データのレベル分布（L1:40 / L2:110 / L3:150）で Σ = 40×0.45 + 110×0.70 + 150×0.89 = 228.5 → 450 + 228.5×1.1 ≒ **701.4**。
- ホームでは大きなアーチ型ゲージ + `Space Mono` の数値。セット終了時に **`612 → 614.4（+2.4 pt）`** とカウントアップアニメーションで差分表示。
- 「TOEIC 公式スコアを保証するものではない、本アプリ内の学習到達度指標」と注記する。

### 6.1 進捗タブに出す数値（すべて実数値で表示）

学習済み語数 / 300、`mastered` 語数、`recognized`（使えない層）語数、通算正解率、認識問題正解率、運用問題正解率、通算学習セット数、連続学習日数、通算学習時間、直近 7 日の日別問題数バー、平均回答秒数。

## 7. デザイン仕様

KouxaPlatform_2（My Growth Lab）のトーン —— **桜色がかった白背景・ローズピンクのプライマリ・大きな角丸・ピル型ボタン・控えめな影・真っ黒を使わない** —— をモバイルに移植する。

### 7.1 カラートークン（`src/theme/colors.ts`）

| トークン | ライト | 用途 |
|----------|--------|------|
| `background` | `#FDFAFB`（桜色がかった白） | 画面背景 |
| `card` | `#FFFDFE` | カード |
| `foreground` | `#5A4A50`（暖色ダークグレー） | 本文（真っ黒を使わない） |
| `primary` | `#D9607A`（ローズピンク） | ボタン・進捗・正解 |
| `band` | `#7A3A4C`（深いローズ） | ヘッダ帯・ゲージの濃色 |
| `secondary` | `#F7EDF0`（淡い桜色） | 補助面・タグ |
| `accent` | `#F0DCD4`（ピンクベージュ） | 強調帯 |
| `muted` | `#8E7A80` | メタ情報 |
| `destructive` | `#C0553C`（落ち着いた朱） | 不正解 |
| `border` | `#EDE0E4` | 罫線・ステッチ |

ダークモードも同トーン（背景 `#2B2226` 等、無彩色の黒にしない）で用意する。

### 7.2 タイポグラフィ

| 用途 | フォント |
|------|----------|
| 画面見出し・出題される英単語（36pt） | **Fraunces**（`@expo-google-fonts/fraunces`, 600/700） |
| 数値・スコア・カウンタ・ラベル | **Space Mono**（`@expo-google-fonts/space-mono`, 400/700） |
| 日本語本文・意味・AI 解説 | **OS 標準**（iOS: Hiragino Sans / Android: Noto Sans JP）。§2 の仕様補足を参照 |

### 7.3 レイアウト規約

- 角丸: カード `24`、ボタンはピル（`999`）、タグ `12`。影は `shadow-sm` 相当（elevation 2）まで。
- 主要 CTA は**画面下部・親指の届く位置**に固定（片手・通勤中の操作を前提）。
- 選択肢は縦 1 列・高さ 64pt 以上のタップ領域。
- 問題カードは reanimated でフリップ（回答時に表→裏で解説面へ）、左右スワイプで「次へ / 前の解説を見る」。
- アニメーションは 200–300ms・過度な演出はしない。

### 7.4 アクセシビリティ

- 正誤は色だけでなく **アイコン（✓ / ✗）と文言**でも示す。
- コントラスト比 4.5:1 以上。フォントスケール（`allowFontScaling`）に追随。
- すべてのタップ要素に `accessibilityLabel`。

## 8. 非機能要件

| 項目 | 要件 |
|------|------|
| 起動時間 | Expo Go で 3 秒以内に操作可能（単語 JSON は同梱・同期読込） |
| 応答性 | 選択肢タップから正誤表示まで 100ms 以内（AI を待たない） |
| オフライン | 出題・回答・進捗はすべてオフラインで完結。AI 部分のみ縮退 |
| API 失敗 | セッションを中断させない。エラーはトースト 1 行に留める |
| データ保護 | 端末外に学習データを送らない（AI へ送るのは当該問題の語・回答・統計値のみで、個人情報は含まない） |
| 保存タイミング | 1 問回答ごとに永続化し、アプリ強制終了でも進捗を失わない |
