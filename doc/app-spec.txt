## 開発したいもの
 -  TOEIC700点突破を目指す社会人向け英単語」のスマートフォンアプリの開発をExpoを使って開発してください。
 - インターネット上で有名な「mikan」、「abceed」、「金のフレーズ2」の構成を参考にしてください。

 - 「今日これをやれば確実に前進している」という実感が得られるもの。

## 注意点
 - 以下の課題点を解消するよう仕様を実装してください。
 --「覚えた」と「使える」は別物です。正解を選ぶだけでは、実際のビジネス場面でその単語を使うイメージが持てません。テストでは解けるのに、長文や会話で出てくると意味がとれないという壁にぶつかる学習者が続出しています。
 -- 間違えた原因がわからないまま次に進んでしまいます。似た単語との混同なのか・品詞の問題なのか・単純に記憶が薄いだけなのか。正誤しかフィードバックされなければ、同じ間違いを繰り返すだけです。
 -- 続けていても、前進している実感が持てません。今日の学習がTOEIC700点にどれだけ近づいたのかを実感できる設計は、まだ業界全体の課題として残っています。

## 実装要件
 - /doc/toeic_wordlist.xlsxのTOEIC頻出英単語リストファイルを使った出題機能があること 。
 - Gemini APIを使ったフィードバック機能が1つ以上実装されていること 。
 - 1回のプレイが10問前後で終わること。
 - 不正解時にGemini APIが「なぜ間違えたか」を分析して返す こと。
 - 正解・不正解にかかわらずGemini APIがビジネス文脈での例文を生成して返すこと。
 - 10問終了後にGemini APIがその日の学習を総括し、次回への一言を返すこと 。
 - 正解率・学習済み単語数など、進捗が数字で見えるUIがあるこtp。
 - 「 覚えた→使えない」「間違えた→理由不明」「続けたのに実感なし」の3課題のうち、少なくとも1つに対して具体的なアンサーがアプリの体験として成立していること。
 - Gemini APIが返すフィードバック・例文・総括コメントが汎用的な一般論に留まっていないこと。
 - 利用者の学習状況に合わせたパーソナライズされた内容（読んだときに「自分のための言葉だ」と感じられる）になっていること。
 - スキマ時間で迷わず使える構成であること。
 - 15分で1回分が終わる設計になっていること。
 - 進捗が数字やビジュアルで把握できること。
 - 既存の英単語アプリには存在しない体験や仕掛けが1つ以上あること。
 
 ## Gemini APIへデータを渡す際の注意点
 - Geminiには先生が生徒に教える役割であること、口調は先生風であることをGemini APIへ渡すこと。
 - 単語・品詞・ユーザーの回答など必要な情報をセットでGemini APIへ渡すこと。
 - Gemini APIへ渡す指示文に上記の意図と工夫を行うこと。

## 技術構成
 - デザインは/frontend-designを使うこと
 - Expo（SDK 54） / Expo Go でのテスト実行を想定。ネイティブビルド不要。
 - ログイン機能は持たせないこと。
 - データベースはなし。全データは端末内の `AsyncStorage` に保存する（オフラインで完結し、サーバー通信を行わない）。
 - フレームワーク:Expo (SDK 54) / React Native 0.81 |
 - 言語 : TypeScript |
 - ルーティング:expo-router（ファイルベースルーティング） |
 - 状態管理:React Context (`WordsProvider`) |
 - データ永続化:`@react-native-async-storage/async-storage`（端末内ローカルストレージ） |
 - アニメーション:react-native-reanimated / react-native-gesture-handler（カードのフリップ・スワイプ） |
 - フォント | Fraunces（見出し）, Space Mono（本文・メタ情報）を `@expo-google-fonts` で読み込み |
